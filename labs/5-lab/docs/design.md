# Клиент-сервер на TCP-сокетах: архитектура

Лабораторная работа №4. Язык C17, Linux (или WSL). Два файла: `client.c` и `server.c`.

## Протокол

Текстовый, две строки, каждая заканчивается `\n`:

```
клиент → сервер:  Client of Ivan Petrov\n42\n
сервер → клиент:  Server of Ivan Petrov\n50\n
```

Сообщение собирается, пока не придут обе строки: TCP может доставить его по частям.
Лимит — 512 байт, имя — до 127 печатных символов, число — целое в диапазоне `int`.
Если клиент закрыл передачу после числа без `\n`, сообщение тоже принимается.
Сумма считается в `long long`, поэтому переполнения нет при любых числах.

## Клиент

`stdin` → проверка, что введено целое число → `getaddrinfo` → `socket` → `connect` →
`send` → `recv` (таймаут 10 с) → разбор ответа → печать имён, чисел и суммы → `close`.
Число вне 1–100 разрешено намеренно: это команда остановки сервера, клиент об этом предупреждает.
Адрес и порт по умолчанию — `127.0.0.1:5555`, можно передать аргументами: `./client 192.168.1.5 5555`.

## Сервер: общая часть

- `CreateListener`: `socket` → `SO_REUSEADDR` → `bind(0.0.0.0:порт)` → `listen`. Слушающий сокет неблокирующий.
- `SignalGuard`: SIGINT и SIGTERM (в режиме 2 ещё SIGCHLD) блокируются через `pthread_sigmask`
  и читаются через `signalfd`. Сигнал — такое же событие, как новый клиент: никаких
  обработчиков, глобальных флагов и гонок.
- `ServeClientBlocking`: таймауты `SO_RCVTIMEO`/`SO_SNDTIMEO` 10 с → приём → разбор → печать →
  `send` → `close`. Результат — ответ дан / команда остановки / ошибка.
- Число вне 1–100: сервер сначала отвечает клиенту, затем закрывает все сокеты и завершается.

## Режимы

**1. Последовательный (базовый).** `poll` ждёт клиента или сигнал, клиент обслуживается целиком,
затем следующий. «Молчащий» клиент держит сервер до 10 с — это ограничение режима.

**2. Процесс на клиента, `fork()` (+1).** Родитель только принимает подключения и вызывает `fork`.
Дочерний процесс закрывает слушающий сокет и signalfd, обслуживает клиента и выходит через `_exit`.
Команду остановки родитель узнаёт по коду выхода 3 при обработке SIGCHLD (`waitpid` с `WNOHANG`),
поэтому зомби-процессов нет. При остановке родитель закрывает слушающий сокет и ждёт всех детей.

**3. epoll + пул потоков (+2).**

```
                основной поток (epoll)                         пул потоков (N = число ядер, 2–16)
 listener ─► accept4(NONBLOCK) ─► Connection ─┐
 signalfd ─► остановка                        │ сообщение собрано:
 eventfd  ─► «клиент попросил остановку»      ├──► Job ─► JobQueue ─► worker: печать, send, close
 timerfd  ─► статистика раз в секунду         │          (mutex + cond)
 клиенты  ─► recv до EAGAIN ──────────────────┘
 таймаут  ─► список соединений по последней активности, epoll_wait ждёт ровно до ближайшего дедлайна
```

- Основной поток не блокируется на `accept`: слушающий сокет, сигналы, пробуждение от рабочих
  потоков и таймер статистики — источники событий одного `epoll`.
- Потоки создаются один раз при старте, на каждое подключение поток не создаётся.
  Очередь задач — кольцевой буфер фиксированного размера: при переполнении клиент получает отказ,
  а не исчерпание памяти.
- Таймауты без активного ожидания: соединения лежат в двусвязном списке по времени последней
  активности (каждый `recv` переносит соединение в конец списка), `epoll_wait` спит ровно до
  дедлайна самого старого. Через 10 с тишины соединение закрывается.
- Статистика — атомарные счётчики (`stdatomic.h`): активные соединения, принято, обработано,
  среднее время обработки (от получения сообщения до отправки ответа), таймауты, отказы.
  Печатается раз в секунду, если что-то изменилось.
- **Ctrl+C**: слушающий сокет закрывается, сервер ждёт активные соединения (не дольше таймаута),
  закрывает очередь, присоединяет рабочие потоки (`pthread_join`), освобождает память и
  дескрипторы. Повторный Ctrl+C закрывает незавершённые соединения сразу.

## Проверка

| Что | Результат |
| --- | --- |
| Полный цикл 42 → сумма 92, 150 → остановка | все три режима |
| `tools/load_test.py`: 20 000 запросов, 1000 одновременно | 0 ошибок, все ответы проверены |
| Буйные клиенты: молчит / половина сообщения / мусор | закрыты через 10 с / 10 с / сразу |
| Ctrl+C при 387 активных соединениях | все 387 дообслужены, 9187 ответов = 9187 обработано |
| valgrind `--leak-check=full --track-fds=yes` | 0 утечек, 0 ошибок во всех режимах, включая дочерние процессы |
| ThreadSanitizer, режим 3 под нагрузкой | 0 предупреждений |

## Сборка и запуск

```bash
cmake -S . -B build -DSTUDENT_NAME="Имя Фамилия" && cmake --build build
./server      # меню: режим, порт [5555], подробный вывод
./client      # во втором терминале: ввести число
```
