# RDTP — надёжная передача файла поверх UDP

Учебная реализация Go-Back-N на C++20, писал кроссплатформенно. 
Есть примеры работы [тут](how-it-works.md).

### Сборка

```bash
cmake -S rdtp -B 7-lab/build -DCMAKE_BUILD_TYPE=Release
cmake --build 7-lab/build -j
```

Если вы уже внутри папки `7-lab/`, используйте
`cmake -S . -B build && cmake --build build -j`. Приложения появятся как
`7-lab/build/rdt_sender` и `7-lab/build/rdt_receiver`.

Важное замечание: в проекте два независимых `main()`. Их следует компилировать
как два отдельных исполняемых файла, как это сделано в локальном
`CMakeLists.txt`. Если родительский CMake без разбора собирает все `.cpp` в один
таргет через `GLOB_RECURSE`, необходимо исключить `7-lab/` из такого общего
таргета и подключить эту папку через `add_subdirectory(rdtp)`.

### Использование

Откройте два терминала. В первом запустите получатель:

```bash
./7-lab/build/rdt_receiver 9000 received_file.txt
```

Во втором терминале запустите отправитель:

```bash
./7-lab/build/rdt_sender 127.0.0.1 9000 file.txt
```

Симуляция потерь и DATA, и ACK (параметры необходимо задать на обеих сторонах):

```bash
./7-lab/build/rdt_receiver 9000 received_file.txt --loss 0.20 --delay-ms 20 --seed 99 -d
./7-lab/build/rdt_sender 127.0.0.1 9000 file.txt --loss 0.20 --delay-ms 20 --seed 42 --window 8 --timeout-ms 120 -d
```

Параметры:

| Параметр         | Назначение                                            | По умолчанию |
|------------------|-------------------------------------------------------|--------------|
| `-d`             | Подробный вывод каждого события                       | Выключен     |
| `--loss X`       | Вероятность потери исходящих дейтаграмм от `0` до `1` | `0`          |
| `--delay-ms N`   | Максимальная случайная задержка дейтаграммы, мс       | `0`          |
| `--seed N`       | Зерно генератора (`0` — случайное)                    | `0`          |
| `--window N`     | Размер окна отправителя в блоках, 1–1024              | `32`         |
| `--timeout-ms N` | Тайм-аут отправителя в миллисекундах, 10–60000        | `250`        |
| `--retries N`    | Лимит попыток, 1–100000                               | `100`        |
| `--linger-ms N`  | Время ожидания повторного FIN получателем, мс         | `2500`       |

`--window`, `--timeout-ms`, `--retries` — только для отправителя,
`--linger-ms` — только для получателя. Можно писать `--loss=0.20` вместо
`--loss 0.20`. Для задержек, превышающих тайм-аут отправителя, ожидаемо
возникают дополнительные повторные передачи. Для больших задержек увеличьте
`--linger-ms` так, чтобы подтвердить повторный FIN.
