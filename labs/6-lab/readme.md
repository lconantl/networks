# DNS Resolver — лабораторная работа №9

Итеративный DNS-резолвер на C++20. Самостоятельно обращается к корневым
DNS-серверам, следует делегированиям NS и находит записи заданного типа.
Системный рекурсивный DNS-резолвер не используется.

По структуре репозитория `networks` эта работа расположена в `labs/6-lab/` (в
исходном PDF она называется лабораторной №9).

Алгоритм перехода с UDP на TCP описан в [docs/design.md](docs/design.md).

## Возможности

| Уровень  | Реализация                                                                                                                                                                                      |
|----------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Базовый  | Итеративное разрешение от root-серверов; запросы с RD=0; A, AAAA, NS, MX, CNAME, TXT, SOA, PTR, SRV, CAA, DS, DNSKEY, RRSIG и TYPEчисло; обработка CNAME, glue, NXDOMAIN и сетевых ошибок; `-d` |
| +1 (кэш) | Локальный файловый кэш результатов с TTL, просмотр `--cache-show` и очистка `--cache-clear`                                                                                                     |
| +2 (TCP) | Проверка флага TC в UDP-ответе, повтор запроса к тому же серверу через TCP, двухбайтовый префикс длины, полное чтение ответа                                                                    |

Код — один файл `dns_resolver.cpp`, конфигурация сборки — `CMakeLists.txt`.
Внешние библиотеки не требуются. Сокеты закрываются автоматически через RAII.

## Сборка (WSL / Linux)

```bash
cd networks/labs/6-lab
cmake -S . -B build
cmake --build build -j
```

Нужны CMake 3.21+, компилятор C++20 с поддержкой `std::format` (например, GCC
13+) и доступ в сеть по UDP/TCP 53. На Windows используйте WSL.

## Запуск

```bash
./dns_resolver example.com A
./dns_resolver example.com AAAA -d
./dns_resolver example.com MX
./dns_resolver example.com NS
./dns_resolver example.com DNSSEC -d
./dns_resolver example.com TYPE257
```

`-d` / `--debug` включает пошаговый вывод **в stderr**: используемый сервер,
делегирование NS, glue-адреса, CNAME, таймауты и переход по TC на TCP. В обычном
режиме в **stdout** печатается только найденный результат (для A/AAAA —
IP-адреса).

`DNSSEC` — учебный псевдоним для запроса **DNSKEY** с EDNS0 DO=1. Он позволяет
получить записи, связанные с DNSSEC, **но не выполняет криптографическую
проверку DNSSEC**. Для самостоятельного запроса DS или RRSIG используйте `DS`
или `RRSIG`.

### Кэш

```bash
./dns_resolver example.com A
./dns_resolver --cache-show
./dns_resolver --cache-clear
./dns_resolver example.com A --no-cache -d
```

Кэш хранится в `.dns_resolver.cache` в текущем рабочем каталоге. Записи с TTL=0
не сохраняются, просроченные не используются. Для наблюдения реальных сетевых
переходов в режиме `-d` используйте `--no-cache`.

### Что показывать при сдаче

1. **Обычное разрешение:** `./dns_resolver example.com A --no-cache`.
2. **Итеративный путь:** `./dns_resolver example.com AAAA --no-cache -d` (root →
   TLD → авторитетный DNS).
3. **TC → TCP:** `./dns_resolver org DNSKEY --no-cache -d` или другой домен с
   крупным ответом, у которого сервер действительно устанавливает TC. Наличие TC
   зависит от конкретного ответа; принудительно гарантировать его этой командой
   нельзя.
4. **Кэш:** повторный запрос, `--cache-show`, `--cache-clear`.

Скриншоты нужно сделать после фактического запуска программы. В папку не
добавлены вымышленные результаты и тестовый код.

## Ограничения

- Домен вводится в ASCII; международные имена предварительно переводятся в
  Punycode.
- Поддерживается класс DNS IN. Не реализованы DNSSEC-валидация цепочки доверия,
  DNS-over-TLS/HTTPS и постоянное кэширование делегирований.
- При отсутствии glue резолвер отдельно ищет IPv4/IPv6 адреса NS. Число
  переходов и глубина рекурсивного поиска NS/CNAME ограничены для защиты от
  циклов.
- Запросы идут напрямую к авторитетным серверам, поэтому доступ к внешнему порту
  53 обязателен. Некоторые сети его блокируют.
